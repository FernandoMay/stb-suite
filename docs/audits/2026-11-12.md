- **TESTEADO:** contract test suite is present and includes full-flow scoring, duplicate participation, zero evidence, forbidden close, resolver rotation authorization, close timing, repeated close/resolve, invalid ID and resolve-before-close cases. This audit did not execute the suite locally.

- **VERIFICADO EN TESTNET:** repository evidence `evidence/sprint3-tombola.json` records a real Testnet E2E from 2026-11-07: contract `CAWSHHKO53IQN2YPQLFHG5YODLI7HYC2POTH6XKX37XJWEVT35WRDBOF`, VRF `CD5K4NNYNG3ZFCET24F3SL6MSYYRD5I2BSWW5K3LFQVIKYHRY2ICVIVX`, request ID 6, drand round 33743971, request tx `5d1a2269ceeab4d4f8e7bd6bfb1326e0c16e533a5c6fa2b52a137539629a8250`, fulfill tx `b0ddcd186677eff98737b0c8283995b9542135e511f1cc7ba43e562b278a4bf2`, and a reproduced winner. This is historical evidence, not a new execution today.
- **PENDIENTE / CRITICAL:** current `contracts/src/lib.rs` still falls back to `last_chunk % participants_len` after eight rejected SHA-256-derived batches. That is a biased modulo route and violates the user's strict randomness gate, even if the probability is extremely small. Also, each raffle snapshots `randomness_provider`, but `request_randomness`/ `fulfill_randomness` read the current global verifier. Provider rotation can therefore break the snapshot invariant. Documentation currently claims the fallback is SHA-256 rejection sampling and is inconsistent with the actual source.

The existing E2E proves the deployed historical flow, but it does not prove the current source WASM is the same deployed WASM. The README records WASM hash `a479665679cc0c7be2546b67e49c6feb309377740c31968d5bf60e119475f801`; this audit did not rebuild the current contract and compare its hash.
