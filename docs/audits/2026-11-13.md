- Soroban prediction lifecycle: create, submit, close, resolve.
- Creator/admin close authorization and `closes_at` rule.
- Resolver is selected by admin and inherited by new predictions; creator cannot choose it.
- Resolver rotation is admin-authorized.
- Participant list is persisted so resolution can update stats.
- `Stats.total/correct/incorrect/points` are persisted.
- Frontend writes use wallet-backed `signAndSend()`.
- Netlify declares Testnet and the correct contract ID.

**TESTEADO**
- Rust unit tests include full flow with scoring, duplicate participation, zero evidence, forbidden close, resolver rotation authorization, early close, repeated close/resolve, and resolve-before-close cases.
- Current package exposes frontend and contract test/build scripts.

**VERIFICADO EN TESTNET**
- Historical Testnet evidence remains documented for deployment, initialization, and creation.
- This run did not execute a fresh E2E transaction, so no new lifecycle verification is claimed.

**PENDIENTE**
- Fresh two-wallet Testnet E2E: create → participate → close → resolve → reread stats.
- Verify live deployed contract/WASM corresponds to the intended source.
- Evidence hash is validated as non-zero 32-byte data, but the contract does not authenticate an external artifact behind that hash.
- Need an explicit Testnet proof of resolver authorization and stats persistence, not only local tests.

### TÓMBOLA

**IMPLEMENTADO**
- Real external VRF interface: request → request ID → fulfillment check → beta → drand round → winner.
- Winner is derived from stored VRF beta, not user input.
- Request ID is persisted per raffle.
- Test module verifies two raffles retain distinct request IDs.
- Test module includes a rejection-sampling case for a biased `0xFFFFFFFF` chunk.
- Netlify declares Testnet and the expected contract ID.

**TESTEADO**
- Rust tests cover request/fulfill flow, per-raffle request association, and rejection sampling.
- Historical evidence reports a real Testnet request/fulfill E2E.

**VERIFICADO EN TESTNET**
- Historical evidence file records:

  - VRF contract `CD5K4NNYNG3ZFCET24F3SL6MSYYRD5I2BSWW5K3LFQVIKYHRY2ICVIVX`
  - request ID 6
  - drand round 33743971
  - request tx `5d1a2269ceeab4d4f8e7bd6bfb1326e0c16e533a5c6fa2b52a137539629a8250`
  - fulfill tx `b0ddcd186677eff98737b0c8283995b9542135e511f1cc7ba43e562b278a4bf2`
  - stored beta and reproduced winner.
- This evidence is dated 2026-11-07 and was not generated anew in this run.

**PENDIENTE / BLOCKER**
- The current `derive_winner_index()` still has a final fallback after eight rejected derivation rounds: `last_chunk % participants_len`. That is a modulo fallback and therefore violates the strict “no biased fallback” gate even if the probability is negligible.
- The raffle snapshots `randomness_provider`, but request/fulfill still read the global verifier. An admin rotation can therefore make the snapshot and the actual provider diverge. Provider binding should be made explicit per raffle or rotation should be constrained until all affected raffles finish.
- Current README/evidence claims “bias zero by construction” while the source still contains the modulo fallback; documentation must not overstate the guarantee.

### BANDERA ROJA

**IMPLEMENTADO**
- On-chain vote is stored per wallet and option.
- On-chain prediction is a separate immutable action.
- Poll close freezes the voting window.
- Result is derived from stored counts, with deterministic lowest-index tie break.
- Canonical result hash is derived from the frozen on-chain snapshot.
- Wallet writes use `signAndSend()`.
- Netlify declares Testnet and the correct contract ID.

**TESTEADO**
- Rust tests cover result derivation, duplicate votes, invalid options, voting after close, deterministic ties, minimum-vote guard, forbidden close, abstention, premature publish, double publish, invalid poll ID, and invalid prediction.

**VERIFICADO EN TESTNET**
- Historical evidence remains documented for deployment/initialization and a result flow.
- No fresh transaction was submitted or independently re-executed in this run.

**PENDIENTE / BLOCKER**
- `Stats.total` is persisted on prediction, but `calculate_score()` remains a derived read returning 100/0; the inspected contract does not persist `Stats.correct` or `Stats.points` when a result is published. Therefore persistent scoring/ranking is not closed.
- README says “votar = off-chain” while the current contract and frontend implementation are on-chain. This is a product/documentation contradiction that must be corrected.
- README badge/explorer link still contains the obsolete contract ID typo even though `netlify.toml` uses the correct ID.
