## TÓMBOLA

This repository currently has a **documentation inconsistency severe enough to block a clean release claim**.

The README says the product uses a Stellar VRF Oracle, drand quicknet and BLS-12-381, and claims rejection sampling with an unbiased SHA-256 fallback. However, the same README later describes:

- `verifiable: bool // siempre false en este MVP`
- `fulfill_randomness(...)` as a mock/documented mock
- `get_winner` as `None` in the “MVP verificado” contract API
- Roadmap item “Integrar VRF Soroban/Testnet verificado” as still unchecked.

Those statements cannot all describe the same release state. This audit therefore does **not** promote the current repository to “fully verified VRF”.

The previously identified provider-binding and modulo-fallback concerns remain pending until the current contract source and deployed WASM are reconciled and tested end-to-end.

## BANDERA ROJA

The current contract documentation/code excerpt establishes the intended architecture clearly:

- `submit_vote` is **on-chain**, public and wallet-authorized.
- `submit_prediction` is a separate **on-chain** prediction.
- `publish_result` derives the winner from on-chain vote counts and computes a reproducible result hash.
- `calculate_score` returns 100/0 based on the stored prediction and winning option.

However, the implementation increments `Stats.total` on prediction and does not show persistence of `Stats.correct` or `Stats.points` during result publication. Therefore persistent scoring/ranking is still not closed.

The Netlify contract ID is correct:

`CA53OBINI3BRK22ZWN2CDGB4Q7QPNW5MH74ZLSHIBIQ35KF5RWBEBOR`

but the README badge still points at a different/invalid contract ID. This is a documentation blocker, not proof that the Netlify environment is wrong.
